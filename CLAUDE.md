# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

`betteralign` is a Go static analysis tool (fork of `fieldalignment`) that detects structs using suboptimal memory layout and optionally rewrites them. It sorts struct fields by descending alignment, then minimizes each value's `ptrdata` — which lowers the GC's scan-work estimate used for pacing (and, on Go before 1.26, also the bytes physically scanned).

`AGENTS.md` is a near-duplicate of this file for OpenCode; keep the two in sync when editing build or architecture notes.

## Commands

The project uses [Task](https://taskfile.dev/) as the build runner.

```sh
task test          # run all tests
task build         # regenerate, format, and build the binary
task lint          # regenerate, format, and run golangci-lint
task fmt           # format code with gci + gofumpt
task generate      # regenerate match_generated.go, then fmt
task update        # go get -u + tidy
```

Direct Go commands:
```sh
go test ./...                      # run tests
go test -run TestApply             # run a single test by name
go test ./internal/dstmin          # test only the reprint engine
go test -bench=. -benchmem ./...   # run benchmarks
go build ./cmd/betteralign         # build without ldflags
```

`go test -race` with `-count` above 1 outlasts the default 10-minute `go test` timeout: pass a larger `-timeout`.

Linting uses `golangci-lint run --timeout 5m` with config in `.golangci.yml` (v2 format). Formatters are `gci` and `gofumpt` (not plain `gofmt`).

### Fuzzing

Native `testing.F` targets, via Task (override `FUZZTIME=2h`, set `CLEAN=true` to clear the coverage cache):

```sh
task fuzz-optimalorder           # FuzzOptimalOrder       (root: layout math)
task fuzz-gcsizes                # FuzzGCSizes            (root: size/ptrdata math)

task fuzz-decoratefilereorder    # internal/dstmin: reorder preserves comments + layout
```

The `afl-fuzz-*` tasks run the same targets under gosentry/LibAFL (`CGO_ENABLED=1`, `GOSENTRY` points at the gosentry `go` binary). `GRAMMAR=true` appends the `golang-nautilus-grammar.json` Nautilus grammar to the LibAFL flags for grammar-based generation. Plain `go test` replays the committed seed corpus under `internal/dstmin/testdata/fuzz/` as ordinary subtests, so it doubles as a regression net.

> Gotcha: `.gitignore`'s unanchored `fuzz/` pattern also ignores `testdata/fuzz/`, so committed fuzz seeds must be added with `git add -f`. Name bug seeds `bugNN_description`.

## Architecture

### Package layout

- **`betteralign` (root)** — the core `analysis.Analyzer`: alignment analysis, layout/ptrdata math, file I/O, flags.
- **`internal/dstmin/`** — the in-tree comment-preserving reprint engine, imported as `dst`. It replaced a `github.com/sirkon/dst` dependency. It decorates an `*ast.File` with per-field byte-range spans, then reprints by byte-splicing reordered struct bodies into the original source and finishing with `go/format.Source`. It supports exactly one mutation (reordering a struct's field list) and deliberately rejects shapes it cannot splice safely (single-line structs, fields sharing a line, block comments crossing a brace, mid-body build constraints / `//line` directives, bodies with `\r`/`\f`/`*//`), and a file with a `\r` anywhere (`ErrCarriageReturn`, from `DecorateFile`: `go/format.Source` would normalise every CRLF in it; `run` treats it as a silent refusal, and `declSource` counts such a file as held, like a `//line` directive — `TestCarriageReturnFileReportOnly`). See `internal/dstmin/README.md`.
- **`internal/diff/`** — verbatim copy of the stdlib's `internal/diff` (the anchored diff behind `gofmt -d`), backing `-diff`. Keep it verbatim apart from the package doc; refresh by re-copying from `$(go env GOROOT)/src/internal/diff`. The one non-doc divergence: `diff_test.go` imports `golang.org/x/tools/txtar` for the stdlib-internal `internal/txtar`.
- **`cmd/betteralign/`** — thin CLI wrapper. Wires up the memory limit (`automemlimit`), handles `-V`/`--version`, and calls `singlechecker.Main(betteralign.Analyzer)`.

### Analysis pipeline

1. The `inspect.Analyzer` traverses the AST; `betteralign` hooks `Preorder` on `*ast.File`, `*ast.GenDecl`, and `*ast.StructType` nodes.
2. Optimality is computed from type info alone, so files without a misaligned struct never read source bytes or build DST. The hot path uses `layoutMetrics`, which decides optimality (and the optimal size/ptrdata) without allocating a field permutation; `optimalOrder` — which allocates the `[]int` permutation that drives the reorder — runs only for a misaligned, rewritable struct (not pinned, not deferred to the test variant). Both share the `compareFieldElem` comparator and a per-pass `gcSizes`, whose memoisation caches are created once per pass and are **not** concurrency-safe.
3. A `dstmin` decorator is built lazily, on the first rewritable misaligned struct in a file, in every mode — the SuggestedFixes need it, not just `-apply`. Reordered files are tracked in `dirtyFiles`; diagnostics are queued in walk order rather than reported immediately.
4. After the walk, one `dst.Reprint` per dirty file yields the whole-file bytes and a `BodyEdit` per reordered struct; each queued diagnostic gets its edit as a `SuggestedFix` (`Rearrange fields`) and is then reported. If `-apply` is set, each file's bytes are atomically written via `github.com/google/renameio/v2/maybe` (atomic on POSIX, best-effort on Windows). With `-diff` (the driver's flag, read via `flagRequested` like `-fix`), nothing is written: each rewrite is printed to `diffOut` (stdout) as a gofmt-style unified diff — or to `diffJSONOut` (stderr) under `-json`, so stdout stays valid JSON — serialised by `diffMu` across concurrent passes. `-diff` without `-apply` does nothing here (under `-fix` the driver prints its own diff from the fixes). `Reprint` re-parses its own gofmt output, so success already guarantees the bytes parse. A failed write (`applyToFile`: not a regular file — a symlink — or a write error) fails the pass: `run` returns the joined errors, so the run exits 1 instead of looking like a report-only run; under `selfWrite` it also prints them, since the driver never reads a pass error under `-fix` (`TestApplyWriteFailureFailsPass`).

### SuggestedFixes from a whole-file reprint

Go's `ast` package does not associate comments with nodes (only byte offsets), so printing a single struct node loses its comments. `internal/dstmin` instead reprints the whole file (splice + `go/format.Source`), and `Reprint` then cuts each reordered struct's brace interior out of that output, matched to the original by `ast.Inspect` index. That text is gofmt's in context — indentation and column alignment included — so the `TextEdit` needs no format pass of its own (some hosts apply edits unformatted); `assertRawFixesMatchGolden` and the reorder fuzz targets check this byte for byte.

`-fix` is therefore the driver's (except with `-generated_files`: the driver refuses fixes in generated files, so `selfWrite` makes `-fix` the v0.15.4 alias of `-apply` there and attaches no fixes; `TestFixWithGeneratedFiles`. Not under `go vet -vettool`: there `-fix -generated_files` stays plain `-fix` and prints a once-per-process note (`vetGeneratedNote`) to stderr — the `ErrApplyUnderVet` it hit before is never read by unitchecker under `-fix`, so the run wrote nothing and exited 0; `run` also clears `generatedFiles` there (`fix && unitcheckerDriver()`), so `declRewritable` predicts a generated partner stays and an importer's side of a conversion to it stays too — it moved alone and broke the build, `TestVetToolSameModulePartnerFollows`): it applies the fixes, merges duplicates from `p` and `p [p.test]`, and implements `-fix -diff`. The analyzer must not write under `-fix` (the driver aborts when a file's size changes underneath it), so `-fix` overrides `-apply`. Under `go vet -vettool` (`unitcheckerDriver`), `run` returns `ErrApplyUnderVet` whenever it would write (`-apply`; `-apply -diff` writes nothing and is allowed, though go vet itself rejects `-diff` without `-fix`): each package is its own process, so a dependency's rewrite landed before an importer predicted from it, the importer's `declAt` missed the moved struct and pinned its side, and the build broke deterministically (`TestVetToolSameModulePartnerFollows`). Fixes are withheld exactly where `-apply` is: pinned structs and passes that defer to the test variant. They are also withheld whenever the analyzer writes itself (`-apply` without `-diff`): a host that sets `apply` and then applies the fixes it collected (golangci-lint's fixer under `--fix`, not a Go flag `flagRequested` can see) edited the rewritten file at offsets an earlier struct's rewrite had shifted, corrupting it (`TestApplyAttachesNoFixes`). A malformed `-exclude_files`/`-exclude_dirs` glob is rejected by `StringArrayFlag.Set` at flag parsing (exit 2, `invalid value … syntax error in pattern`): the pass error `normalizeExcludePaths` returns is never read under `-fix`, so such a run exited 0 having fixed nothing. `normalizeExcludePaths` still fails the run for a pattern only cleaning breaks (`foo\/`; it used to exclude every file and exit 0; `TestNormalizeExcludePathsRejectsBadPattern`); `isExcluded`'s fail-toward-excluded stays as the backstop.

Because `dstmin` now runs in every mode, three guards keep it from hurting a plain report: its source cache (`readSourceOnce`) is keyed by parse (`*token.File`), not just path, so a long-running host that re-parses after an edit rereads the file instead of splicing older bytes that would revert a same-length edit; `DecorateFile` refuses source that no longer matches the parsed AST (`sourceMatchesAST`: length, identifiers, basic literals and braces — a file edited mid-run used to panic with an out-of-range slice, and a same-length tag or array-length edit in a host's unsaved buffer, absent from the disk bytes the fix is cut from, was reverted: `TestDecorateFileRejectsStaleTag`), and `run` calls dstmin through `decorateFile`/`reprint`, which convert a panic into `ErrRewritePanic` (logged; that file loses its fix, the diagnostic stays). `validEdit` backstops the checker, which panics on an invalid fix.

The rewrite runs only when something takes it (`rewrite := apply || fixesWanted(pass)`): under the x/tools CLI drivers (`cliDriver`: global flags parsed, with `-fix`, `-json` and `-c` registered — a test binary registering a stand-in `-fix` does not count) in plain report mode (no `-fix`, `-diff`, `-json` or `-apply`) the checker prints text and discards fixes, so `run` skips the deferral check, decoration and the whole-file `Reprint` (a quarter of a report-only run's CPU). Diagnostics are identical either way (`TestFixesWanted`); programmatic hosts (golangci-lint, gopls, analysistest) always get fixes. `Reprint`'s validation re-parse stays.

The deferral check reads the package directory (`testFilesInDir`), cached per directory and revalidated by its stamp through `loadStamped` (one entry per directory; concurrent passes share one scan — the earlier check-then-store re-parsed every test file per pass, a 4× slowdown on the stdlib, pinned by `TestTestFilesInDirScansOnce`). The per-path caches of partner sources and excluded-build scans (`declSourceCache`, `otherBuildCache`) use the same `loadStamped`, so an edit replaces an entry instead of adding one (`TestLoadStampedOneEntryPerPath`). Those parses (`newDeclSource`, `scanOtherBuildSrc`) build comments only when the source holds a marker a comment reader needs (`parseMode`: `betteralign:`, `DO NOT EDIT`, `//line `, `/*line `, `go:linkname`); `linkTarget` reads a per-file map (`linkTargets`) built once.

### Field sort order (`compareFieldElem`)

Fields are sorted **stably** by the `compareFieldElem` comparator (shared by `layoutMetrics` and `optimalOrder`):
1. Zero-sized types first
2. Higher alignment first
3. Pointer-bearing types before pointer-free types
4. Among pointer-bearing types, fewer trailing non-pointer bytes first (minimises GC ptrdata)
5. Larger size first

A multi-name field (`A, B int`) moves as one grouped declaration — the reorder never splits it.

### Nested structs: one-run convergence

A struct held by value inside another is measured at the layout the run will leave it in, not as declared (`gcSizes.projected`, wired in `run` through `gcSizes.rewritten`). Measured as declared, the outer order was chosen for an inner layout the same run then changed, so the next run moved the outer again: 14 of 75 corpus modules changed on a second `-fix`, x/tools needed four runs, and a CI check failed right after `-fix`. `TestApplyIsFixedPoint` (second `-apply` over `a`, `layoutpin`, `nested` changes nothing), `TestNested`/`TestApplyNested` (fixture `testdata/src/nested/`) and `TestNestedConversionStaysInStep` pin it. It assumes gofmt-clean input: on a non-gofmt'd file the first run's reprint (`go/format.Source`) normalises shapes both dstmin and the prediction refused (fields sharing a line, a field on a brace line, a `/* */` crossing `}`), so a second `-apply` may reorder them and their outers.

The prediction must agree in every pass: the two sides of a cross-package conversion hold the same field types and must sort them identically. So it uses only what every pass sees alike — `rewriteCandidate` on the declared struct literal (the generic declaration for an instance; type aliases of struct literals count, since they are rewritten too) plus `declRewritable`: the declaring package is in the run (`sameRun`), its file passes the run's filters (test/generated suffixes, excludes, the generated-code header read from disk), and the declaration is a type spec's multi-line struct without `betteralign:ignore` on its brace line, beside no in-package test file that doesn't parse (`brokenTest`), in a file without a `//line` directive (`declSource`: a parse of the file really holding it — unadjusted position — judged with `run`'s own predicates, `hasIgnoreCommentAST` and `lineDirective`, and found by its first field's line and name; cached per path, revalidated by size/mtime). `declRewritable` also requires dstmin to accept the declaration's shape (`declSource.decorated`): a refused shape stays as declared, so an outer holding it — a private one included — is measured against it as is (`multiComment`/`crossBrace` in `nested/refused.go`; the outer used to be laid out for an inner layout that never materialised, its pointer bytes rising 32 → 40). `declRewritable` and `declOptedIn` both locate the declaration through `declAt`, so they judge the same text. It takes the first field's unadjusted line and tries, in order, the file on disk (cached per path, revalidated by size/mtime) and its pre-rewrite bytes (`pristineSource`, keyed by path, stored by `storePristine` before each `-apply` write; latest wins unless the bytes are identical; the entry parses lazily). A candidate is accepted when it declares a struct whose first field has that name on that line and — except under a vettool — has the size of the declaration's `token.File`. Disk first: after an edit in the same process the disk is current and the pristine entry stale (`TestApplyAfterEditInSameProcess`, `TestDeclAtPrefersDisk`); after another pass's concurrent rewrite the moved struct no longer matches the disk, so the pristine bytes are used (`TestReadDeclSourcePrefersPristine`); a struct the rewrite left in place matches both and both say the same. Pristine is loaded after the disk read, so a read racing the write still finds it. The entry used to be keyed by the writer's `*token.File`, which go/packages shares within a load but golangci-lint does not (it parses each package variant itself), so an importer read the already-rewritten file (`TestDeclAtSeparateParses`). The size rejects export data under the source-parsing drivers (singlechecker, golangci-lint): gcimporter's fake `token.File` (64 KiB, one-byte lines) means the package is not analyzed and never rewritten (`TestDeclRewritableExportData`, `TestExportDataPartnerPinsConversion`, which builds the binary since analysistest loads every dependency from source). Under `go vet -vettool` (`unitcheckerDriver`: the process got exactly one `*.cfg` argument, as x/tools' singlechecker checks before handing off to unitchecker) every import is export data and each package is vetted by its own process, so the size is skipped and the text alone decides (`TestVetToolSameModulePartnerFollows`); vetting a subset of a module leaves partners outside the pattern unrewritten while the local side follows, as in v0.15.4. A file with a `//line` directive is never rewritten, by `run` either: export data keeps only `//line`-mapped positions, so another pass can't locate its declarations (`TestLineDirectivePartnerPinsConversion`, `TestLineDirectiveWithoutColumn`, once BUG-45's panic). A text scan used here before missed an ignore comment holding a `{` or sitting above a `/* */` line, and took any `{`-free line for the brace. **Pins and test-variant deferral are deliberately not consulted for an outer struct that could have a partner** — any struct whose field names are all exported; only the declaring package sees them — so there a pinned inner struct is measured as reordered although it never is (5 such structs across the 75-module corpus; `HS` in `nested/private.go` shows it). **This package's pins — not the test-variant deferral — are consulted for a private outer** (`private`: an unexported field name — blank, lowercase or an embedded unexported type): unexported names from different packages are never identical (spec, "Type identity"), so no other package can hold a struct identical to it and no other pass has to agree on its order. `run` measures such a struct with a second `gcSizes`, `localSizes` (own memo caches; its `rewritten` is `rewritable` plus, for a struct declared in this package, a `rewriteCandidate` and not in `ensureLayoutPins()` — the candidate check first, so an aligned inner doesn't force the pin walk), for `rewriteCandidate`, the message figures and `optimalOrder`. `collectLayoutPins` → `foreignRewritten` keeps the shared, pin-free `sizes`. `localSizes.rewritten` never consults `rewriteDeferred`, and needn't: a private outer is rewritten by one pass only — its package's, or under deferral the test variant, measuring with its own pins. When an inner struct is pinned only by an in-package `_test.go` (a literal the base pass cannot see), the base pass measures a private outer as if the inner moved and keeps reporting it — with no fix, since it defers — even after the variant has left the outer at its real optimum, so that diagnostic persists across runs: noise, never a wrong rewrite, accompanying the duplicate (base plain, variant caveated) already documented for the pinned inner itself. Convergence holds: a pinned inner never moves and the private outer was laid out for exactly that (`hs`/`hsKept` in `nested/private.go`, under `TestApplyIsFixedPoint`; `hsKept` is `crypto/tls.clientHandshakeState`'s shape, which went 192 → 208 pointer bytes before). Known ceiling: an exported-only struct between them (private P holds M holds pinned I) is rewritten with the pin-free figures while P measures it with local ones, so P's figures can be off there (still convergent: a projection is the optimum's figures, the same in every run). `-opt_in` disables the projection, since another package's opt-in marks are invisible. Diagnostic figures are in the same projected terms. Tried and rejected: refusing an order that, with inner structs measured as declared, comes out larger or with more pointer bytes (`gcSizes.declared`/`worseAsDeclared`). It refused an outer struct in run 1 when its inner struct in the same package really was reordered (as declared the order looks worse), then accepted it in run 2 once the inner's declared layout equalled the projected one — breaking one-run convergence (the `Time`/`Outer` case in `nested.go`); it can't consult pins without drifting across passes, and its size half never fired (no rewritten struct grew in std, x/tools, x/net, x/text or 3M random trials). `projected` unaliases first: an alias of a defined type is measured like the type, and an alias of a struct literal is projected (its declaration is rewritten) while a struct literal written in place is not.

### Green Tea GC diagnostic wording

The pointer-bytes diagnostic is framed by the **analyzed** package's Go version, not betteralign's own. `targetGoVersion` reads it as the newer of the per-file `//go:build go1.x` constraint (`ast.File.GoVersion`) and the module's `go` directive (`pass.Pkg.GoVersion()`) — an older constraint is a minimum the module's own version already exceeds, so `go1.20` in a `go 1.26` module reads go1.26 — and `greenTeaGC` gates on `>= go1.26` (via `go/version`, guarding invalid strings with `version.IsValid`). For Go 1.26+ targets — where the Green Tea GC marks by span rather than per value — the message drops the *N bytes saved* claim and reads `struct with N pointer bytes could be M (lowers GC scan-work estimate)`; older/unknown targets keep the classic wording. Size diagnostics never change. Coverage: `TestGreenTeaWording` (with the `//go:build go1.26` fixture under `testdata/src/greentea/`) plus internal unit tests in `version_internal_test.go`.

### Composite-literal safety

A struct constructed anywhere in the package via a *positional* composite literal (`T{1, 2, 3}` rather than keyed) is reported but **never** rewritten — no `-apply` rewrite and no SuggestedFix — since reordering would silently re-map the literal's elements. The diagnostic points at the offending literal.

That includes the package's files the current build excludes (another `GOOS`/`GOARCH`, an unset build tag), which type checking never sees: `otherBuildPositional` parses them (the load's own `pass.IgnoredFiles`, not `go/build`'s defaults, which miss a file a run's `-tags` negates — `TestOtherBuildPositionalNegatedTag`; same package name, cached per file under a `sync.OnceValue`; a file under `//go:build ignore` (or, with no `//go:build` line, the legacy `// +build ignore`), excluded from every build, is skipped — `neverBuilt`, which is also why `TestApplyRewritesWhenTestFileBuildExcluded` uses that constraint) and pins by type path: a type name plus a step per elided level, resolved against the package's types (`resolveLiteralPath`; a visited set of paths per call keeps a declaration cycle spread over several excluded files linear — it was exponential in their number, `TestResolveLiteralPathCycleAcrossFiles`), so `[]T{{...}}` and a named container's `Ts{{...}}`/`M{{...}: v}` count, also when the container is declared only in an excluded file (its type declarations are kept and followed syntactically) or is a generic instance (`List[T]{{...}}`: a step landing on a type parameter continues from the argument's name); `layoutPin.at` carries the location, since those files aren't in the pass's `FileSet`. Rewriting std on darwin used to break `os` on Windows (`ProcessState`, built positionally in `exec_windows.go`). Fixture `testdata/src/otherbuild/`, `TestOtherBuildPositional`. Assembly stubs are found the same way: `scanOtherBuild` records each body-less `FuncDecl`'s receiver, parameter and result types by local name (stripped of `*`, `[]`, `[N]`, `...`: `asmOperandName`; selector types skipped), and `collectLayoutPins` resolves them like literal paths and pins with `pinLayout` (`pinAssembly`, the struct and what it holds by value); a name the package scope declares is also walked like an in-build operand (`pinLayout(elemOf(...))`), since `resolveLiteralPath` ends in `canonicalStructType`, nil for a named slice or array (`type HS []HElem; func h(x HS)` in `asmstub_arm64.go`) — such stubs are usually arch-gated (`f_arm64.go` + `f_arm64.s`), so the in-build check alone missed the main case (`asmstub_never.go`). Only positional literals, assembly stubs, linkname pushes and the Go functions an excluded `.s` file calls (see Layout pins) are found syntactically; the other type-based contracts (`Offsetof`, conversions, codecs) in excluded files stay invisible.

The check scans only the current pass's files, and go/packages runs the analyzer once per variant — base `p` (non-test files) and `p [p.test]` (non-test + in-package test files). Since the base pass can't see a positional literal in an in-package `*_test.go`, `deferToTestVariant` makes the base pass skip **only the rewrite** — `-apply` and the SuggestedFix — (not reporting) whenever the package directory holds such a test file this pass does not hold, leaving the rewrite to the `[p.test]` variant, which sees the tests. Reporting is deliberately **not** deferred: if the base pass went silent and the driver then skipped the `[p.test]` variant as ill-typed (e.g. a test file broken mid-edit), healthy non-test code would get no diagnostic at all — an earlier whole-package deferral did exactly that and was reverted. The trade-off is a possible duplicate diagnostic for a struct pinned by a test literal: the base reports it plain, the variant with the `reorder skipped` caveat. The test files come from disk (`testFilesInDir`: in-package by package clause, not in `pass.Files`, not in `pass.IgnoredFiles` — the load's own constraint evaluation, `-tags` included — and not under `//go:build ignore` or a lone legacy `// +build ignore`), not from the FileSet: golangci-lint parses packages lazily into one shared FileSet, so a base pass run before the variant was parsed missed the tests and rewrote a struct only a test literal pins (`TestDeferToTestVariantLazyParse`, `TestDeferToTestVariantSkips`). A package directory holding an in-package test file with a syntax error (`brokenTest`: `scanTestDir`'s `broken`, judged by package clause and `neverBuilt` alone — not `pass.Files` or `pass.IgnoredFiles` — so every pass reads the same disk) is rewritten by no pass, under `-test=false` and in the variant too: the driver skips the ill-formed variant, so the base pass rewrote a struct a positional literal in a test file pins (in the broken file or a healthy sibling), and `go test` failed once the file was fixed (`TestSyntaxErrorTestFileNotRewritten`). Its structs are still reported, without a fix and like a deferral without a caveat (a caveat would need the test-file scan in report-only mode, and diagnostics must not depend on the mode, `TestFixesWanted`); a once-per-directory stderr note (`deferNoted`) says why. `declRewritable` predicts such a struct stays, so an importer's side of a conversion stays too (`TestSyntaxErrorTestFileHoldsPartner`; before this rule, the deferral was cancelled instead, for that test). A type error fails the variant too, but only type checking can tell, so that still defers — a known limitation (see Cross-package conversions). Under the driver's `-test=false` (`flagIs`, either flag set) no variant runs and the base pass keeps the rewrite. A pass whose `pass.Files` already holds a `*_test.go` is the variant and keeps the rewrite before the directory is consulted: gopls leaves `pass.IgnoredFiles` nil, so a GOOS- or tag-excluded in-package test (`w_windows_test.go`) is in neither list and the variant used to defer too, leaving no pass to offer the fix (`TestDeferToTestVariantVariantOwnsRewrite`). File arguments (`betteralign -apply p/p.go`) load `command-line-arguments` and never a variant, so there the deferral is final: it stays (safe), and a once-per-directory stderr note (`deferNoted`) says to run on the package instead (`TestDeferToTestVariantFileArgsNote`, `TestFileArgsDeferNote`); ordinary package paths stay silent, since their variant normally follows. Literals in *external* test packages (`package p_test` in p's directory) load as another package no pass of `p` sees, so they are read from disk too (`extTestPositional`: `testFilesInDir`'s entries of package clause `p_test`; `scanExtTest`, cached per file and package path through `loadStamped`, matches `imp.T{...}`, `*imp.T` and elided `[]imp.T{{...}}` under the file's own qualifier for `p`'s import path, renamed or dot-imported, via `positionalLits`, shared with `scanOtherBuildSrc`; a file with a syntax error is scanned as far as it parses; under file arguments `p` is `command-line-arguments`, which go list gives no module, so the import path is the nearest `go.mod`'s module path plus the directory, `TestExtTestPositionalBinary`) and pin like an excluded file's literal (`layoutPin.at`); base pass and variant read the same disk and agree (`TestExtTestPositional`, whose in-package test file makes the variant exist; cloudflare/circl `zk/dleq`). The xtest's own types (`type L []p.T; L{{...}}`) and generic instances (`p.G[int]{...}`) are not followed. Positional literals of exported structs in ordinary importing packages remain the documented cross-package limitation.

### Layout pins

Beyond positional literals, these layout contracts stop a rewrite. Each is checked only on the misaligned path:

- **`structs.HostLayout`** — a direct field of that type (blank, named, embedded, or via alias) means the C-ABI layout is the contract: the struct is **neither reported nor rewritten** (`hasHostLayout`). Per the `structs` docs the marker does not propagate to enclosing structs.
- **Blank padding** — a `_` field of non-zero size (cache-line or alignment pad) makes the waste deliberate: like `HostLayout`, the struct is **neither reported nor rewritten** (`hasBlankPadding`), since its "could be" figure would require moving the pad. Zero-sized blank markers (`_ [0]func()`, `_ noCopy`) don't count.
- **`unsafe.Offsetof(x.f)`** anywhere in the package (files `-exclude_files`/`-exclude_dirs` skip included, like positional literals) pins x's struct and every embedded struct on the path to a promoted `f`, but not `f`'s own type (`collectLayoutPins`, which also gathers positional literals; first use in source order wins). Reported with a `reorder skipped: unsafe.Offsetof at …` caveat. An `Offsetof` in an in-package `*_test.go` follows the positional-literal deferral exactly, including its duplicate-diagnostic trade-off (base pass plain, `[p.test]` variant caveated).

- **64-bit atomics** — `&x.f` (or `&x.f[i]` into an array field; not a slice's separately allocated elements) passed to a 64-bit `sync/atomic` function (`isAtomic64Func`: `AddInt64`, `LoadUint64`, …) pins x's struct and the embedded path like `Offsetof` (`pinFieldPath`, shared by both), and every struct holding it by value on the way (`&s.t.f`, `&s.ts[i].f`; a pointer's target is its own allocation — except a pointer variable `resolveLocal` resolves to `&y.f`, `&y.f[k]` or `&y`, which points into y's: `cache := &d.recent[k]; atomic.LoadUint64(&cache[i])` is std's `internal/bisect.dedup`, panicking on 386 once `m` moved first, and `t := &s.t; &t.n` with `t` an inline struct, which `holdsAtomic` doesn't see; one hop, shared with the word's own; a pointer into a slice field's elements still pins nothing, fixture `indirect/` `ViaElemPtr`/`ViaRowPtr`/`ViaFieldPtr`/`ViaSlicePtr`), also through a pointer conversion (`(*int64)(&s.d)`): 386, arm and 32-bit mips need f 8-byte aligned, which only an allocation's first word guarantees, so a reorder on amd64 made the 32-bit build panic at run time. Every local struct holding an atomic-pinned struct by value (fields, arrays, inline struct literals) is pinned too, to the fixed point (`holdsAtomic`): the access usually sits in the inner struct's own method (`func (c *Counter) Inc()`), out of sight of the holder. That includes another package's struct (`go.uber.org/atomic.Int64`, `struct{ _ nocmp; v int64 }` with `atomic.AddInt64(&i.v)`; std's `os.file` and `net.netFD` holding `internal/poll.FD`, whose `fdMutex.state` is a `LoadUint64` word): `foreignAtomic` finds the access syntactically in the declaring package's directory (`declDir`: the first field's unadjusted file, `$GOROOT/` from export data mapped through `goroot`, which falls back to `go env GOROOT` for a `-trimpath` betteralign build; under `GOFLAGS=-trimpath`, common in CI, export data names files by import path and `untrimmed` maps them back: `mod@version/rest` to `GOMODCACHE` (env, else `go env`; case-escaped by `module.EscapePath`/`EscapeVersion`), else to `vendor/mod/rest`; `pass.Module.Path/rest` to `Module.Dir` (else the `go.mod` above the pass's own file: vet before Go 1.27 sets no `Dir`); a dot-less std path to `GOROOT/src`; anything else to the main module's `vendor/` if present, `TestUntrimmed`; `atomicFieldsInDir`: non-test `.go` files, build-excluded ones too, not `//go:build ignore`, those without `"sync/atomic"` never parsed, cached per directory by its stamp like `testDirCache`, with the same in-place-edit ceiling), collecting every field name selected on the way to a 64-bit call's word under the file's own qualifier (renamed or dot import; `&x.f`, `&x.f[i]`, `&x.t.f`, through any one-argument call as a conversion; one hop through a name the call's declaration assigns an address — `v := &e`, `v = &e`, `var v = &e` — then walked the same way: `cache := &d.recent[k]; atomic.LoadUint64(&cache[i])`, `p := &x.f; atomic.AddInt64(p, 1)`; fixture's `Dedup`/`ViaElemPtr`), then matching the foreign struct's fields by name and recursing by value into the structs it holds (memoised per pass, which also ends recursion). By name, so a same-named field of another struct of that package over-pins; under `-trimpath` another go.work module or a module `replace`d to a local directory trims to its bare module path, is not resolved and pins nothing. Fixture `testdata/src/xatomic/` (`TestCrossPackageAtomicHolder`); std gains exactly the `os.file` and `net.netFD` pins (`GOARCH=386 -apply -diff os` used to move `pfd` to offset 12). The typed `atomic.Int64`/`Uint64` are aligned by the compiler and don't pin; `gcSizes` mirrors that rule (`isAlign64`: the `align64` marker type from `sync/atomic` or the runtime's atomic package is itself 8-aligned, as in go/types, so a struct holding it is 8-aligned and padded to a multiple of 8 even where `MaxAlign` is 4), which 32-bit runs previously mis-sized (special-cased only as a field, `struct{_ align64; a int32; v int64}` came out 12 on 386, not 16: `TestGcSizesAlign64Marker`). With it, an 8-aligned `atomic.Int64` sorts ahead of 4-aligned pointers and can raise ptrdata (`struct{p *int; x atomic.Int64}`: 4 → 12, reported as "-8 bytes saved"), so `rewriteCandidate` refuses an optimum that is larger, or the same size with more pointer bytes — size, the real memory, still wins (`TestRewriteCandidateNeverWorse`; on 386 std it drops `runtime/tracestring.go`'s "-4 bytes saved" and keeps `net/http`'s 88 → 80); `FuzzOptimalOrder` checks under 64-bit, 32-bit and projected sizes that nothing else can.
- **Type identity** — Go requires identical field order for conversions between struct types and for assignability between a struct and an identical unnamed struct type (a literal type or an alias `type A = struct{...}`). `collectLayoutPins` pins both sides of a conversion between distinct struct types, and every struct identical to an unnamed one (a `TypeSpec` with `Assign` counts as unnamed). Unnamed struct types reached through imported objects (another package's parameter, result, variable or field, via `TypesInfo.Uses`) join the check, so passing a local struct to `func F(x struct{...})` pins it. A named type the package references is opened one level (a struct's fields, a slice/map/func's elements) for positional `dep.Holder{h}` and `dep.List{e}`; named types inside it are not, so an unnamed struct buried deeper doesn't over-pin (any assignment to it references its own level). Two identical *named* types are only linked by an explicit conversion, so they stay independent otherwise. Instances join the check too (`TypesInfo.Instances`): `G[int]`'s struct is identical to `struct{p *int}` and `F[int]`'s parameter type to a local struct, though the generic declarations spell `*T`; they pin through the declaration. A type parameter counts as every struct of its type set (`structsOf`): `P{1, 2}` and `P(s)` with `P interface{ S }` pin S like a literal or conversion of S. As for conversions, a foreign side `foreignRewritten` predicts to move (an alias `type A = struct{...}` there) takes the local side with it instead of pinning it. Without this, an ignored/excluded/pinned side broke the build (`net/http` converts to `http2.Config`).
- **Memory layout / wire format** — a conversion to or from `unsafe.Pointer` (type punning), and an argument of an `orderCodecs` function (`encoding/binary` Read/Write/Size/Append/Encode/Decode, `encoding/asn1` Marshal/Unmarshal[WithParams], `x/crypto/ssh` Marshal/Unmarshal) pin the struct and, via `pinLayout`, every struct it holds by value (arrays included; pointers are not followed; for ASN.1, slice fields too — SEQUENCE OF). So does every parameter, result and receiver type of a body-less `*ast.FuncDecl` (an assembly stub; unwrapped through pointers and slices like a codec argument, slices inside not followed; `pinAssembly`): hand-written `.s` files read fields at offsets the Go layout fixes, and build, vet and asmdecl all stay silent when they move (klauspost/compress zstd and huff0 segfaulted after `-apply`). Only a top-level function (`fn.Recv == nil`: a linkname cannot name a method, so a body-less method sharing a linknamed function's name stays pinned) that a two-argument `//go:linkname fn target` in its file pulls from its own package (`linkTarget`: the doc comment, then every comment, since gofmt can detach a directive; `selfLinked`: `target` has prefix `pass.Pkg.Path()+"."`) is Go compiled against the real layout and pins nothing (std: the badlinkname self-references in `net/http`, go/types, reflect). A one-argument directive (assembly, or a push to a package keeping its own copy: math/big `addVV`, internal/cpu `riscvHWProbe` ↔ the runtime's `riscvHWProbePairs`) and a pull from another package (`plugin.doInit` ↔ `runtime.initTask`) keep the pin, as does no directive (`sync.notifyList`). The same check runs in excluded files: `scanOtherBuild` records each stub's `linkTarget` (`asmStub`) and `collectLayoutPins`, which knows the package path, pins from the first stub per operand name that is not `selfLinked`. Fixtures: `layoutpin/asm.go`, `otherbuild/asmstub_never.go`, and `linkself/` for the exempt same-package pull (`TestLinknameSelf`; analyzed in place, since `copyTestPackage`'s copies change the package path the target names). The codec check runs before the arity check: `binary.Size` takes one argument. Both unwrapping loops stop on a revisited defined type (`revisits`): `type S []S` used to hang the pass.
- **One hop of indirection** — the codec, 64-bit atomic and `unsafe.Pointer` sinks (`sinkArgs`, shared by the direct call and the hops; `pinOperand` pins what an operand reaches) also see an operand one step away. A variable of this package given its operand once (`p := &s.n; atomic.AddInt64(p, 1)`, `var v any = &h; binary.Read(r, le, v)`, `var addf = atomic.AddInt64; addf(&s.n, 1)`) resolves to it (`resolveLocal` over `singleDefs`, built lazily once per pass: exactly one assignment, at the declaration, one value per name; any `=`, `op=`, `++`, range clause, multi-value call or `&v` disqualifies it, `TestIndirectPins`' `Reassigned`). A function of this package whose (non-variadic) parameter is itself a sink operand is a forwarder (`forwarders`, keyed by `fn.Origin()` and index; `func readLE(r io.Reader, v any) error { return binary.Read(r, le, v) }`, `func add(p *int64)`, a method too), and its callers' arguments, collected during the walk (`localCalls`) and matched after it, pin as at the sink; a generic forwarder's argument has the instance's type (`enc(Gen{})`, `bytesOf(p)`). Nothing deeper: a forwarder passing its parameter to another forwarder, a callback (`gadd(&s.n, func(p *int64) { atomic.AddInt64(p, 1) })`), a value stored in a field or a parameter merely read (`peek(v any)`, the control) pin nothing. Pointer arithmetic from a field's address — `unsafe.Pointer(&p.A)` as the operand of a `uintptr(...)` conversion (`unsafe.Pointer(uintptr(unsafe.Pointer(&p.A)) + 8)`) or the first argument of `unsafe.Add` (`fieldArith`; either side may be a variable `resolveLocal` resolves) — pins p's struct via `pinFieldPath`. A bare `unsafe.Pointer(&x.f)` (`(*[N]byte)(unsafe.Pointer(&x.f))`, a syscall buffer) depends only on f's own layout and pins nothing around f: pinning it cost xxh3's `Hasher` (80 bytes), netlink's `XfrmAlgo` ×3 and `TcPedit` and three x/sys/unix `Sockaddr*` their rewrites (fixture's `FieldBytes`); a `uintptr(unsafe.Pointer(&x.f))` passed straight to a syscall still pins, accepted. At the conversion only — through a forwarder the pointer is opaque (the runtime's `goparkunlock(&s.lock, ...)` would pin every lock holder). The bare-address rule also dropped std's three runtime field-address pins (`racereleasemerge(unsafe.Pointer(&g.inc))`, `raceacquire(unsafe.Pointer(&s.lock))`, the `(*unsafe.Pointer)(unsafe.Pointer(&s.p))` atomic-pointer idiom); runtime is toolchain-fixed anyway, and std's report-only output is otherwise unchanged. Fixture `testdata/src/indirect/`.
- **reflect field index** — `reflect.TypeOf(x).Field(c)`, `reflect.ValueOf(x).Field(c)`, through any `.Elem()` chain (`ValueOf(&x).Elem().Field(c)`), and `reflect.TypeFor[T]().Field(c)`, with `c` a constant, pin x's (T's) struct (`reflected`, `pinReflect`: `reorder skipped: reflect field index at …`). `FieldByName` survives a reorder and doesn't pin; `FieldByIndex`, `NumField` loops and a `reflect.Value` passed around stay invisible. Fixture `indirect/` (`R1`–`R3`, control `ByName`).
- **ASN.1 structs** — `isASN1Struct` (an `asn1` tag, or a field of an `encoding/asn1` type — directly, behind a pointer, or as an array/slice element (`[]asn1.RawValue`, `[2]asn1.ObjectIdentifier`; `isASN1Type`) — on the struct or on any struct it holds by value — fields, arrays, slice elements, not pointers; `revisits` guards recursion, the first hit stops) makes `rewriteCandidate` reject the struct outright, because its encoder usually lives in another package (`crypto/x509` encodes `crypto/x509/pkix` types), where the call-site pin can't reach. Found by rewriting the standard library: reordered PKCS#8 structs broke TLS key parsing. The by-value walk came from x/crypto/pkcs12, whose `encryptedData` holds the tagged `encryptedContentInfo` and reaches `asn1.Unmarshal` through an `interface{}`. That walk deliberately over-suppresses: `crypto/x509.Certificate` (40 bytes to save) holds pkix types by value and stays unreported, though std never passes it to `asn1.Marshal`. `isASN1Type` counts only the package's exported data types (`RawValue`, `RawContent`, `ObjectIdentifier`, `BitString`, `Enumerated`, `Flag`; not the error types or unexported ones), so inside `encoding/asn1` itself `taggedEncoder` (field type `encoder`) is reported (`TestIsASN1Type`).
- **SSH structs** — `hasSSHTag` (an `ssh` or `sshtype` tag) makes `rewriteCandidate` reject the struct, for the same reason as ASN.1: `ssh.Marshal` is usually reached through an interface.
- **XML structs** — `isXMLStruct` (an `xml` tag on the struct or on any struct it holds by value: `isASN1Struct`'s walk, now `taggedStruct(str, key, marker, visited)`) makes `rewriteCandidate` reject the struct: encoding/xml writes child elements in field order, which a schema's `xs:sequence` fixes, and `xml.Marshal` is reached through an interface or from another package (rewriting x/net/webdav changed its XML output). encoding/json key order, fmt `%+v` and reflection order are observable too but deliberately not pinned (Doc/README caveat). Fixture `layoutpin/xmltag.go`.
- **Punning one indirection further** — the `unsafe.Pointer` conversion pin unwraps the pointer's element through `elemOf` (pointers, slices; `pinLayout` takes arrays), both directions — from `unsafe.Pointer` in the conversion arm, to it in `pinOperand` (the `pinUnsafe` sink, so a forwarder's argument and a `resolveLocal` variable unwrap too): `*(*[]T)(p)` reads a slice header whose elements are T (`runtime/metrics.Value` ↔ the runtime's `metricValue`), likewise `**T` and `unsafe.Pointer(&s)` with `s []T`. `*[N][]T` stays unwrapped one level only. - **Assembly references** — each `·name(SB)` the package's `.s` files reference (`asmRefs`: `pass.OtherFiles` plus the `.s` files in `pass.IgnoredFiles`, cached per path by `loadStamped` in `asmRefCache`; `scanAsmRefs` skips comments, `TEXT`/`DATA`/`GLOBL` definition lines, `pkg·name` of another package — a preceding letter, `.`, `/` or `∕` — and `//go:build ignore` files) pins, via `pinSignature` (the stub rule's receiver/param/result walk, `elemOf` + `pinLayout`), a function's signature, a func-typed variable's signature (`var cbPC = cb`), or another variable's own type (read at `·v+off(SB)`): a Go callback handed an argument block the assembly filled at fixed offsets (purego's `callbackArgs`) is checked by nothing. A name declared only in an excluded `.go` file resolves syntactically: `scanOtherBuildSrc` records every top-level function's and func-typed variable's operand type names (`otherBuild.funcs`; `var v = f` copies f's within the file), resolved by `pinOperandName` like a stub's. Fixture `testdata/src/asmcall/` (`TestAsmCallback`, analyzed in place since `copyTestPackage` copies only `*.go`).
- **Linkname pushes** — a function *with* a body carrying a two-argument `//go:linkname local target` whose target is in another package (not `selfLinked`) implements that package's body-less declaration (`runtime.reflect_rselect` is `reflect.rselect`; the declaration side was already pinned as a stub), so its own operand structs mirror that side's: pinned by `pinSignature` (`pinLinkPush`), except an exported named operand when the target's package (`linkPackage`) is not among the package's transitive imports (`mirrorFree`, `pass.Pkg.Imports()` walked once per pass): such a package may import this one and name the type itself, which then follows a reorder (`testing/synctest`'s `testingSynctestTest(*testing.T)`, `net/http_test`'s `transportFromH1Transport(*Transport)` over-pinned `testing.common` and `http.Transport` before that exclusion). vet.cfg names no pattern) — or both std / both GOPATH; a partner known only from export data is not in the run under the source-parsing drivers (`declAt`'s size check), but is under `go vet -vettool`, where every import is export data; ### Type-parameter layouts

A generic struct whose layout depends on a type parameter is reported by neither report-only nor `-apply`. `layoutDependsOnTypeParam` (called only on the misaligned path, so non-generic structs pay nothing) walks the field types and returns true when a type parameter appears in a **by-value** position — directly (`B T`), inside an array (`B [4]T`), or inside a by-value struct. Such fields are sized from the constraint's underlying (`T any` → `interface{}`, 16 B / ptrdata 16), so size/ptrdata would be per-instantiation guesses. Indirections (`*T`, `[]T`, `map[K]T`, `chan T`) have a fixed layout regardless of the type argument and are **not** suppressed. A type parameter is matched *before* `Underlying()` is consulted, since `TypeParam.Underlying()` is the constraint's interface, not the parameter.

### Magic comment annotations

- `// betteralign:ignore` inside a struct's opening brace — skip this struct entirely.
- `// betteralign:check` on the `type` declaration — required when `-opt_in` is set; placing it on a `type ( … )` group opts in every spec inside.

### Testing

Analyzer tests live in `betteralign_test.go` (package `betteralign_test`) and use `golang.org/x/tools/go/analysis/analysistest`.

- `TestSuggestions` — runs the analyzer on `testdata/src/a` and checks `// want` annotations match diagnostics.
- `TestApply` — copies `testdata/src/a/*.go` to a temp dir, runs `-apply`, and compares against `*.go.golden` via `gotest.tools/v3/golden`.
- Architecture-specific files (`a_amd64.go`, `a_arm64.go`) are filtered to the current `runtime.GOARCH`.
- Flag-specific tests cover `-exclude_dirs`, `-exclude_files`, and `-opt_in` under `testdata/src/exclude/` and `testdata/src/optin/`.
- `internal/dstmin` carries its own decoration/reprint unit tests plus `TestReorderCrashersDoNotPanic`, which replays a local crash corpus.

When adding analyzer test cases: add a `.go` file under `testdata/src/a/` with `// want` annotations, and a corresponding `.go.golden` with the expected post-apply output.
