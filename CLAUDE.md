# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

`betteralign` is a Go static analysis tool (fork of `fieldalignment`) that detects structs using suboptimal memory layout and optionally rewrites them. It sorts struct fields by descending alignment, then minimizes each value's `ptrdata` — which lowers the GC's scan-work estimate used for pacing (and, on Go before 1.26, also the bytes physically scanned).

`AGENTS.md` is a near-duplicate of this file for OpenCode; keep the two in sync when editing build or architecture notes.

## Commands

The project uses [Task](https://taskfile.dev/) as the build runner.

```sh
task test          # run all tests
task build         # regenerate, format, and build the binary
task lint          # regenerate, format, and run golangci-lint
task fmt           # format code with gci + gofumpt
task generate      # regenerate match_generated.go, then fmt
task update        # go get -u + tidy
```

Direct Go commands:
```sh
go test ./...                      # run tests
go test -run TestApply             # run a single test by name
go test ./internal/dstmin          # test only the reprint engine
go test -bench=. -benchmem ./...   # run benchmarks
go build ./cmd/betteralign         # build without ldflags
```

Linting uses `golangci-lint run --timeout 5m` with config in `.golangci.yml` (v2 format). Formatters are `gci` and `gofumpt` (not plain `gofmt`).

### Fuzzing

Native `testing.F` targets, via Task (override `FUZZTIME=2h`, set `CLEAN=true` to clear the coverage cache):

```sh
task fuzz-optimalorder           # FuzzOptimalOrder       (root: layout math)
task fuzz-gcsizes                # FuzzGCSizes            (root: size/ptrdata math)
task fuzz-reorderableat          # FuzzReorderableAt      (root: declaration text check, BUG-45)
task fuzz-decoratefileidentity   # internal/dstmin: decorate→reprint round-trips
task fuzz-decoratefilereorder    # internal/dstmin: reorder preserves comments + layout
```

The `afl-fuzz-*` tasks run the same targets under gosentry/LibAFL (`CGO_ENABLED=1`, `GOSENTRY` points at the gosentry `go` binary). `GRAMMAR=true` appends the `golang-nautilus-grammar.json` Nautilus grammar to the LibAFL flags for grammar-based generation. Plain `go test` replays the committed seed corpus under `internal/dstmin/testdata/fuzz/` as ordinary subtests, so it doubles as a regression net.

> Gotcha: `.gitignore`'s unanchored `fuzz/` pattern also ignores `testdata/fuzz/`, so committed fuzz seeds must be added with `git add -f`. Name bug seeds `bugNN_description`.

## Architecture

### Package layout

- **`betteralign` (root)** — the core `analysis.Analyzer`: alignment analysis, layout/ptrdata math, file I/O, flags.
- **`internal/dstmin/`** — the in-tree comment-preserving reprint engine, imported as `dst`. It replaced a `github.com/sirkon/dst` dependency. It decorates an `*ast.File` with per-field byte-range spans, then reprints by byte-splicing reordered struct bodies into the original source and finishing with `go/format.Source`. It supports exactly one mutation (reordering a struct's field list) and deliberately rejects shapes it cannot splice safely (single-line structs, fields sharing a line, block comments crossing a brace, mid-body build constraints / `//line` directives, bodies with `\r`/`\f`/`*//`). See `internal/dstmin/README.md`.
- **`internal/diff/`** — verbatim copy of the stdlib's `internal/diff` (the anchored diff behind `gofmt -d`), backing `-diff`. Keep it verbatim apart from the package doc; refresh by re-copying from `$(go env GOROOT)/src/internal/diff`.
- **`cmd/betteralign/`** — thin CLI wrapper. Wires up the memory limit (`automemlimit`), handles `-V`/`--version`, and calls `singlechecker.Main(betteralign.Analyzer)`.

### Key files

| File | Purpose |
|------|---------|
| `betteralign.go` | Analyzer definition, `run()` entrypoint, reorder/rewrite, layout/field sort (`layoutMetrics`, `optimalOrder`, `compareFieldElem`), GC size/ptrdata (`gcSizes`) |
| `internal/dstmin/dstmin.go` | `Decorator` / `DecorateFile` / `Fprint` — decoration, comment routing, splice-based reprint |
| `match_generated.go` | **Generated** — DFA matcher for `// Code generated by … DO NOT EDIT.` comments. Regenerate with `task generate` (the `rec` tool); do not edit by hand. |
| `golang-nautilus-grammar.json` | Nautilus grammar for grammar-based LibAFL fuzzing (see Fuzzing) |
| `cmd/betteralign/main.go` | Entry point; sets GOMEMLIMIT from cgroup/system |

### Analysis pipeline

1. The `inspect.Analyzer` traverses the AST; `betteralign` hooks `Preorder` on `*ast.File`, `*ast.GenDecl`, and `*ast.StructType` nodes.
2. Optimality is computed from type info alone, so files without a misaligned struct never read source bytes or build DST. The hot path uses `layoutMetrics`, which decides optimality (and the optimal size/ptrdata) without allocating a field permutation; `optimalOrder` — which allocates the `[]int` permutation that drives the reorder — runs only for a misaligned, rewritable struct (not pinned, not deferred to the test variant). Both share the `compareFieldElem` comparator and a per-pass `gcSizes`, whose memoisation caches are created once per pass and are **not** concurrency-safe.
3. A `dstmin` decorator is built lazily, on the first rewritable misaligned struct in a file, in every mode — the SuggestedFixes need it, not just `-apply`. Reordered files are tracked in `dirtyFiles`; diagnostics are queued in walk order rather than reported immediately.
4. After the walk, one `dst.Reprint` per dirty file yields the whole-file bytes and a `BodyEdit` per reordered struct; each queued diagnostic gets its edit as a `SuggestedFix` (`Rearrange fields`) and is then reported. If `-apply` is set, each file's bytes are atomically written via `github.com/google/renameio/v2/maybe` (atomic on POSIX, best-effort on Windows). With `-diff` (the driver's flag, read via `flagRequested` like `-fix`), nothing is written: each rewrite is printed to `diffOut` (stdout) as a gofmt-style unified diff — or to `diffJSONOut` (stderr) under `-json`, so stdout stays valid JSON — serialised by `diffMu` across concurrent passes. `-diff` without `-apply` does nothing here (under `-fix` the driver prints its own diff from the fixes). `Reprint` re-parses its own gofmt output, so success already guarantees the bytes parse.

### SuggestedFixes from a whole-file reprint

Go's `ast` package does not associate comments with nodes (only byte offsets), so printing a single struct node loses its comments. `internal/dstmin` instead reprints the whole file (splice + `go/format.Source`), and `Reprint` then cuts each reordered struct's brace interior out of that output, matched to the original by `ast.Inspect` index. That text is gofmt's in context — indentation and column alignment included — so the `TextEdit` needs no format pass of its own (some hosts apply edits unformatted); `assertRawFixesMatchGolden` and the reorder fuzz targets check this byte for byte.

`-fix` is therefore the driver's (except with `-generated_files`: the driver refuses fixes in generated files, so `selfWrite` makes `-fix` the v0.15.4 alias of `-apply` there and attaches no fixes; `TestFixWithGeneratedFiles`): it applies the fixes, merges duplicates from `p` and `p [p.test]`, and implements `-fix -diff`. The analyzer must not write under `-fix` (the driver aborts when a file's size changes underneath it), so `-fix` overrides `-apply`. Fixes are withheld exactly where `-apply` is: pinned structs and passes that defer to the test variant.

Because `dstmin` now runs in every mode, three guards keep it from hurting a plain report: its source cache (`readSourceOnce`) is keyed by parse (`*token.File`), not just path, so a long-running host that re-parses after an edit rereads the file instead of splicing older bytes that would revert a same-length edit; `DecorateFile` refuses source that no longer matches the parsed AST (`sourceMatchesAST`: length, identifiers and braces — a file edited mid-run used to panic with an out-of-range slice), and `run` calls dstmin through `decorateFile`/`reprint`, which convert a panic into `ErrRewritePanic` (logged; that file loses its fix, the diagnostic stays). `validEdit` backstops the checker, which panics on an invalid fix.

The deferral check (`testFilesByDir`) now runs in report-only mode too, so its per-`FileSet` scan is built under a `sync.OnceValue`; the earlier check-then-store let concurrent passes all miss and re-parse every test file (a 4× slowdown on the stdlib, pinned by `TestTestFilesByDirBuildsOnce`).

### Field sort order (`compareFieldElem`)

Fields are sorted **stably** by the `compareFieldElem` comparator (shared by `layoutMetrics` and `optimalOrder`):
1. Zero-sized types first
2. Higher alignment first
3. Pointer-bearing types before pointer-free types
4. Among pointer-bearing types, fewer trailing non-pointer bytes first (minimises GC ptrdata)
5. Larger size first

A multi-name field (`A, B int`) moves as one grouped declaration — the reorder never splits it.

### Nested structs: one-run convergence

A struct held by value inside another is measured at the layout the run will leave it in, not as declared (`gcSizes.projected`, wired in `run` through `gcSizes.rewritten`). Measured as declared, the outer order was chosen for an inner layout the same run then changed, so the next run moved the outer again: 14 of 75 corpus modules changed on a second `-fix`, x/tools needed four runs, and a CI check failed right after `-fix`. `TestApplyIsFixedPoint` (second `-apply` over `a`, `layoutpin`, `nested` changes nothing), `TestNested`/`TestApplyNested` (fixture `testdata/src/nested/`) and `TestNestedConversionStaysInStep` pin it.

The prediction must agree in every pass: the two sides of a cross-package conversion hold the same field types and must sort them identically. So it uses only what every pass sees alike — `rewriteCandidate` on the declared struct literal (the generic declaration for an instance; type aliases of struct literals count, since they are rewritten too) plus `declRewritable`: the declaring package is in the run (`sameRun`), its file passes the run's filters (test/generated suffixes, excludes, the generated-code header read from disk), and the declaration is multi-line without `betteralign:ignore` on its brace line (`declSource.reorderableAt`, from the file text, cached by path/size/mtime; column 0 — unknown, after a `//line` directive without one — skips the single-line test: it used to panic, BUG-45, `TestLineDirectiveWithoutColumn`). **Pins and test-variant deferral are deliberately not consulted** — only the declaring package sees them — so a pinned inner struct is measured as reordered although it never is (5 such structs across the 75-module corpus; the `offsetof.go` fixture shows it). `-opt_in` disables the projection, since another package's opt-in marks are invisible. Diagnostic figures are in the same projected terms. `projected` unaliases first: an alias of a defined type is measured like the type, and an alias of a struct literal is projected (its declaration is rewritten) while a struct literal written in place is not.

### Green Tea GC diagnostic wording

The pointer-bytes diagnostic is framed by the **analyzed** package's Go version, not betteralign's own. `targetGoVersion` reads it from the per-file `//go:build go1.x` constraint (`ast.File.GoVersion`) if present, else the module's `go` directive (`pass.Pkg.GoVersion()`), and `greenTeaGC` gates on `>= go1.26` (via `go/version`, guarding invalid strings with `version.IsValid`). For Go 1.26+ targets — where the Green Tea GC marks by span rather than per value — the message drops the *N bytes saved* claim and reads `struct with N pointer bytes could be M (lowers GC scan-work estimate)`; older/unknown targets keep the classic wording. Size diagnostics never change. Coverage: `TestGreenTeaWording` (with the `//go:build go1.26` fixture under `testdata/src/greentea/`) plus internal unit tests in `version_internal_test.go`.

### Composite-literal safety

A struct constructed anywhere in the package via a *positional* composite literal (`T{1, 2, 3}` rather than keyed) is reported but **never** rewritten — no `-apply` rewrite and no SuggestedFix — since reordering would silently re-map the literal's elements. The diagnostic points at the offending literal.

That includes the package's files the current build excludes (another `GOOS`/`GOARCH`, an unset build tag), which type checking never sees: `otherBuildPositional` parses them (`build.Default.MatchFile`, same package name, cached per directory under a `sync.OnceValue`; a file under `//go:build ignore`, excluded from every build, is skipped — `neverBuilt`, which is also why `TestApplyRewritesWhenTestFileBuildExcluded` uses that constraint) and pins by type name, elided `[]T{{...}}` included; `layoutPin.at` carries the location, since those files aren't in the pass's `FileSet`. Rewriting std on darwin used to break `os` on Windows (`ProcessState`, built positionally in `exec_windows.go`). Fixture `testdata/src/otherbuild/`, `TestOtherBuildPositional`. Only positional literals are found this way; type-based contracts (`Offsetof`, conversions, codecs) in excluded files stay invisible.

The check scans only the current pass's files, and go/packages runs the analyzer once per variant — base `p` (non-test files) and `p [p.test]` (non-test + in-package test files). Since the base pass can't see a positional literal in an in-package `*_test.go`, `deferToTestVariant` makes the base pass skip **only the rewrite** — `-apply` and the SuggestedFix — (not reporting) whenever such a test file is loaded, leaving the rewrite to the `[p.test]` variant, which sees the tests. Reporting is deliberately **not** deferred: if the base pass went silent and the driver then skipped the `[p.test]` variant as ill-typed (e.g. a test file broken mid-edit), healthy non-test code would get no diagnostic at all — an earlier whole-package deferral did exactly that and was reverted. The trade-off is a possible duplicate diagnostic for a struct pinned by a test literal: the base reports it plain, the variant with the `reorder skipped` caveat. Because the deferral keys on *loaded* test files, a driver run with `-test=false` loads none and the base pass no longer defers. Literals in *external* test packages (`package p_test`) load separately and never rewrite `p`'s structs, so they remain the documented cross-package limitation — as are positional literals of exported structs in ordinary importing packages.

### Layout pins

Beyond positional literals, three layout contracts stop a rewrite. Each is checked only on the misaligned path:

- **`structs.HostLayout`** — a direct field of that type (blank, named, embedded, or via alias) means the C-ABI layout is the contract: the struct is **neither reported nor rewritten** (`hasHostLayout`). Per the `structs` docs the marker does not propagate to enclosing structs.
- **Blank padding** — a `_` field of non-zero size (cache-line or alignment pad) makes the waste deliberate: like `HostLayout`, the struct is **neither reported nor rewritten** (`hasBlankPadding`), since its "could be" figure would require moving the pad. Zero-sized blank markers (`_ [0]func()`, `_ noCopy`) don't count.
- **`unsafe.Offsetof(x.f)`** anywhere in the package (excluded files included, like positional literals) pins x's struct and every embedded struct on the path to a promoted `f`, but not `f`'s own type (`collectLayoutPins`, which also gathers positional literals; first use in source order wins). Reported with a `reorder skipped: unsafe.Offsetof at …` caveat. An `Offsetof` in an in-package `*_test.go` follows the positional-literal deferral exactly, including its duplicate-diagnostic trade-off (base pass plain, `[p.test]` variant caveated).

- **64-bit atomics** — `&x.f` (or `&x.f[i]` into an array field; not a slice's separately allocated elements) passed to a 64-bit `sync/atomic` function (`isAtomic64Func`: `AddInt64`, `LoadUint64`, …) pins x's struct and the embedded path like `Offsetof` (`pinFieldPath`, shared by both): 386, arm and 32-bit mips need f 8-byte aligned, which only an allocation's first word guarantees, so a reorder on amd64 made the 32-bit build panic at run time. The typed `atomic.Int64`/`Uint64` are aligned by the compiler and don't pin; `gcSizes` mirrors that rule (`isAlign64`: a field of the `align64` marker type from `sync/atomic` or the runtime's atomic package makes its struct 8-aligned even where `MaxAlign` is 4), which 32-bit runs previously mis-sized. With it, an 8-aligned `atomic.Int64` sorts ahead of 4-aligned pointers and can raise ptrdata (`struct{p *int; x atomic.Int64}`: 4 → 12, reported as "-8 bytes saved"), so `rewriteCandidate` refuses an optimum that is larger, or the same size with more pointer bytes — size, the real memory, still wins (`TestRewriteCandidateNeverWorse`; on 386 std it drops `runtime/tracestring.go`'s "-4 bytes saved" and keeps `net/http`'s 88 → 80); `FuzzOptimalOrder` checks under 64-bit, 32-bit and projected sizes that nothing else can.
- **Type identity** — Go requires identical field order for conversions between struct types and for assignability between a struct and an identical unnamed struct type (a literal type or an alias `type A = struct{...}`). `collectLayoutPins` pins both sides of a conversion between distinct struct types, and every struct identical to an unnamed one (a `TypeSpec` with `Assign` counts as unnamed). Unnamed struct types reached through imported objects (another package's parameter, result, variable or field, via `TypesInfo.Uses`) join the check, so passing a local struct to `func F(x struct{...})` pins it. A named type the package references is opened one level (a struct's fields, a slice/map/func's elements) for positional `dep.Holder{h}` and `dep.List{e}`; named types inside it are not, so an unnamed struct buried deeper doesn't over-pin (any assignment to it references its own level). Two identical *named* types are only linked by an explicit conversion, so they stay independent otherwise. Without this, an ignored/excluded/pinned side broke the build (`net/http` converts to `http2.Config`).
- **Memory layout / wire format** — a conversion to or from `unsafe.Pointer` (type punning), and an argument of an `orderCodecs` function (`encoding/binary` Read/Write/Size/Append/Encode/Decode, `encoding/asn1` Marshal/Unmarshal[WithParams]) pin the struct and, via `pinLayout`, every struct it holds by value (arrays included; pointers are not followed; for ASN.1, slice fields too — SEQUENCE OF). The codec check runs before the arity check: `binary.Size` takes one argument. Both unwrapping loops stop on a revisited defined type (`revisits`): `type S []S` used to hang the pass.
- **ASN.1 structs** — `isASN1Struct` (an `asn1` tag, or a field of an `encoding/asn1` type) makes `rewriteCandidate` reject the struct outright, because its encoder usually lives in another package (`crypto/x509` encodes `crypto/x509/pkix` types), where the call-site pin can't reach. Found by rewriting the standard library: reordered PKCS#8 structs broke TLS key parsing.
- **Cross-package conversions** — a pass sees its imports, never its importers, so the other package's pass reorders its struct regardless. `foreignRewritten` predicts that (`sameRun`: the same module, a module of the active `go.work` — its `use` directories, found as the go command finds `go.work`, matched against the partner's nearest `go.mod` (never found through a `vendor` directory: `go work vendor` vendors into a root that may be `use .`), from the object's export-data position — or both std / both GOPATH; plus `rewriteCandidate`, plus `declRewritable` through `gcSizes.rewritten` when projection is on — an ignored, generated or excluded partner stays put, so the local side stays pinned), and then the local side is *not* pinned: identical fields sort identically, so both reorder in step. Pinning it instead broke `go build std` (`net/http.HTTP2Config` → `net/http/internal/http2.Config`). `rewriteCandidate` is shared by `run` and this prediction so they can't drift. Mispredicting "not in the run" is the dangerous direction (local side pinned, partner reordered — a build v0.15.4 left intact, as module-path-only `sameRun` did for workspaces); a module merely `replace`d to a local directory is correctly not in the run (`TestSameRunWorkspace`).

Coverage: `TestLayoutPins` / `TestApplyLayoutPins` (fixture `testdata/src/layoutpin/`, 64-bit only) and the `-diff` tests `TestApplyDiff`, `TestApplyDiffJSON`, `TestFixDiffGlobalFlags`, `TestDiffWithoutApply`, which reach unexported state through `export_test.go`.

### Type-parameter layouts

A generic struct whose layout depends on a type parameter is reported by neither report-only nor `-apply`. `layoutDependsOnTypeParam` (called only on the misaligned path, so non-generic structs pay nothing) walks the field types and returns true when a type parameter appears in a **by-value** position — directly (`B T`), inside an array (`B [4]T`), or inside a by-value struct. Such fields are sized from the constraint's underlying (`T any` → `interface{}`, 16 B / ptrdata 16), so size/ptrdata would be per-instantiation guesses. Indirections (`*T`, `[]T`, `map[K]T`, `chan T`) have a fixed layout regardless of the type argument and are **not** suppressed. A type parameter is matched *before* `Underlying()` is consulted, since `TypeParam.Underlying()` is the constraint's interface, not the parameter.

### Magic comment annotations

- `// betteralign:ignore` inside a struct's opening brace — skip this struct entirely.
- `// betteralign:check` on the `type` declaration — required when `-opt_in` is set; placing it on a `type ( … )` group opts in every spec inside.

### Testing

Analyzer tests live in `betteralign_test.go` (package `betteralign_test`) and use `golang.org/x/tools/go/analysis/analysistest`.

- `TestSuggestions` — runs the analyzer on `testdata/src/a` and checks `// want` annotations match diagnostics.
- `TestApply` — copies `testdata/src/a/*.go` to a temp dir, runs `-apply`, and compares against `*.go.golden` via `gotest.tools/v3/golden`.
- Architecture-specific files (`a_amd64.go`, `a_arm64.go`) are filtered to the current `runtime.GOARCH`.
- Flag-specific tests cover `-exclude_dirs`, `-exclude_files`, and `-opt_in` under `testdata/src/exclude/` and `testdata/src/optin/`.
- `internal/dstmin` carries its own decoration/reprint unit tests plus `TestReorderCrashersDoNotPanic`, which replays a local crash corpus.

When adding analyzer test cases: add a `.go` file under `testdata/src/a/` with `// want` annotations, and a corresponding `.go.golden` with the expected post-apply output.
